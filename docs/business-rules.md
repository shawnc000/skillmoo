# Business rules

These invariants protect the credibility of the public SkillMOO engine.

1. Static grade is not runtime efficacy. Never invent or generalize an effectiveness claim from static analysis.
2. Capability is not malicious intent. Legitimate key, network, file, or shell use may require review; a block requires a real malicious signal.
3. Grade and safety gate are separate. Evidence scope must state whether only `SKILL.md` or the full bundle was analyzed.
4. Optimization is verify-or-reject and must never silently write user Skill files or worsen protected invariants.
5. CLI analysis is deterministic and locally auditable. Any optional network behavior must be explicit, content-minimized, and disableable.
6. Ratings are never for sale. Commercial hosted features must not alter the static score.
7. The executable rubric constants are authoritative. Public methodology must remain coupled through `eval:methodology`.
8. Private gold labels, efficacy answer keys, accumulated outcome data, credentials, hosted services, and strategy are outside this public repository.
9. A shared-engine change is incomplete until the intended private/public parity and package-version consequences are documented and tested.
10. Automatic matching may use only A/B, safety-gate PASS, low-risk entries and must abstain when evidence is weak; negated capabilities must survive retrieval.
11. A manifest-only pass cannot override a failed complete-package gate. Such a Skill is excluded from automatic matching and cannot be embedded as installable content.
12. `inspected`, `verified-here`, and cross-environment evidence are distinct. A recommended combination is not runtime-verified unless that exact ordered setup was measured.
13. Remote URLs are references, not installable artifacts. Setup accepts complete local directories or content-addressed embedded artifacts only.
14. Setup is preview-first, exact-confirmation, no-code-execution, drift-detecting, and recoverable. Receipts and caches are private local state, not platform signatures.
15. Embedded third-party content requires immutable source identity, exact bytes, license evidence, full-bundle gate approval, and package-version binding.
16. Manifest-screened catalog entries are not complete-package-inspected artifacts. Mutable source URLs and unknown package evidence must remain visible to users.
17. Published reports must use anonymous ordinal labels and omit local paths, Skill names, details, evidence snippets, raw content, and content-derived changes.
18. Verification identity binds all regular package files; network requests refuse redirects and non-transient retries and stay inside hard aggregate budgets.
19. Discovery caps, unreadable eligible files, and incomplete bundles fail closed. Partial evidence cannot receive a clean grade, report, optimization, or setup plan.
